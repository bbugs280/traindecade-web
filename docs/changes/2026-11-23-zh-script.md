# 2026-11-23 — ZH site rendered Simplified Chinese in a Traditional site

## The bug

Vincent sent a screenshot of the pagination button:

```
© 2026 訓練十年 · 關於 · 聯絡 · 私隱政策                      ← Traditional
                                          [ 下一页 » ]      ← Simplified
```

Both scripts in one screen. The footer was Traditional; the button directly
above it was Simplified.

## Root cause — Hugo resolves the THEME's i18n on key collision

`themes/PaperMod/i18n/zh.yaml` ships **Simplified** Chinese:

```yaml
- id: next_page
  translation: "下一页"     # 页 not 頁
- id: home
  translation: "主页"
- id: code_copy
  translation: "复制"
```

**Adding the same ids to `i18n/zh.yaml` does NOT fix it.** Hugo resolves the
theme's value when a key exists in both. Proven, not assumed:

```
1. Added next_page: 下一頁 to i18n/zh.yaml        → still rendered 下一页
2. Replaced it with MARKER_NEXT                    → marker never rendered
3. But `about` / `privacy` DID render from that
   same file — because the theme has no such ids
```

So: **the project i18n file only supplies ids the theme does not define.**
Theme-owned labels can only be fixed by owning the layout.

Attempts that did **not** work, so nobody repeats them:

- adding `languageCode: zh-HK` → Hugo then looks for `i18n/zh-HK.yaml`
- quoting the translation values to match the theme's format → no change
- `hugo --gc --ignoreCache` → not a cache issue
- stripping comments from `i18n/zh.yaml` → not a parser issue

## The fix — own the layouts

| File | Replaces | Label |
|---|---|---|
| `layouts/list.html` | theme pagination | 上一頁 / 下一頁 |
| `layouts/partials/post_nav_links.html` | theme post nav | 上一頁 / 下一頁 |
| `layouts/partials/breadcrumbs.html` | theme breadcrumbs | 主頁 |
| `layouts/partials/translation_list.html` | theme lang switcher | 語言: |
| `layouts/partials/extend_footer.html` | (ours) code-copy relabel | 複製 / 已複製！ |

Labels are **hardcoded, not `i18n`**. That is a deliberate trade: a third
language would not translate these automatically, but a Hong Kong reader seeing
简体 in a 繁體 site is a visible defect, while a missing third language is a
feature nobody has asked for.

## The test — `tests/test_zh_traditional_script.py`

Scans every rendered ZH page for simplified-only characters (36-char curated
set). Proven RED→GREEN.

**Two design decisions inside it, both learned the hard way:**

**1. It scans VISIBLE text, not raw HTML.** A `<script>` block that matches
`复制` in order to *replace* it is the fix, not a defect. Scanning raw output
flagged my own fix as a leak.

**2. Unicode escapes do not survive `--minify`.** Writing
`LEGACY_COPY = "\u590d\u5236"` to keep the source clean failed — the minifier
collapses escapes back into literal characters. Stripping script bodies is the
only check that measures what a reader actually sees.

⚠️ **This gate is the only thing stopping a PaperMod upgrade from silently
reintroducing Simplified.** Every new theme id leaks until overridden. Nothing
errors — the site just looks wrong to a Hong Kong reader.

## Note on the i18n file

`i18n/zh.yaml` was **left unchanged**. Adding theme ids there would look like a
fix and do nothing — worse than not trying, because the next person would
believe the file was authoritative for labels it cannot control.
