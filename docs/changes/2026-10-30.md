# 2026-10-30 — traindecade: functional-independence cluster was a dead end; grip becomes a hub

**Card:** `Traindecade: Topic Discovery → approve (Stage 3 gate) · 3×/week`
**Candidate executed:** Candidate 1 from the 2026-10-30 08:02 discovery readout — but
**re-scoped mid-flight**, see "Where the cron's plan was wrong" below.
**Type:** internal-link structure fix. **Not** a new post, **not** a tune.

## The defect

The functional-independence cluster was a **straight line with a dead end**:

```
BEFORE
  balance ──→ grip ──→ muscle-power        (nothing pointed back to grip)
  mobility ──→ joint-friendly, snowboard   (outside the cluster entirely)
  core     ──→ (no outbound links at all)  (unreachable from the cluster)
```

`grip` held **2 inbound / 1 outbound** in each language. Three of the four
functional-independence posts hung off one thread, and `mobility` + `core`
were structurally unreachable from the cluster.

⚠️ **`core-strength` had ZERO outbound internal links** — a total orphan in
outbound terms, which no prior sweep had flagged because it had 3 inbound
and therefore never appeared on an orphan report.

## Where the cron's plan was wrong

The cron proposed "finish the fan-out" as if `grip` were untouched. **It had
been edited 2 days earlier** — commit `0b0a68b`, the AWGS age-stratification
fix (see `2026-10-28.md`), `lastmod` 2026-10-28T22:45.

GSC lags ~3 days, so the 30-day pull the cron built its plan from **could not
see that edit**. This is the tune-lever trap (stale data → re-propose shipped
work) now firing on the **link** lever.

**What survived the check:** the cron's structural read was correct on every
count — grip genuinely did have 2-inbound/1-outbound, and nothing linked
grip→balance/mobility/core. The numbers were right; only the "untouched"
premise was wrong. The fix proceeded because the defect was real, not because
the plan was.

## Every link is anchored in an argument, not a footer

Link count without a reason is SEO theatre. Each anchor states *why* the next
post follows from the current one:

```
grip → balance    "force is no use to a man who's on the floor —
                   grip and power both assume you stay upright"
grip → core       "if your grip number is low because sitting switched
                   off your trunk, that's the upstream cause"
balance → core    "the place they both start is your trunk"
core → grip       "grip is measured in your hands, but the force has to
                   travel through a trunk that can hold position"
core → balance    "you can't hold a single-leg stance on a spine that's
                   busy compensating"
```

## ⚠️ One self-inflicted error, caught and reverted

A `patch` call aimed at the **EN** balance post was written with the **ZH**
replacement string, which inserted Chinese text into the English file **and
deleted the sentence** `The uncomfortable truth: …`. Caught immediately by
diffing before continuing; reverted in place; `git diff --stat` then showed
only the 2 intended grip files. **Lesson: when editing an EN/ZH pair, write
one file per call and read the diff text, not just `success: true`.** The
tool reported success on the broken edit.

⚠️ **Grep pitfall that cost a turn:** verifying links in `public/` with
`href="/posts/…"` returns **nothing** — `hugo --minify` strips attribute quotes,
so the rendered form is `<a href=/posts/<slug>/>`. Match on
`<slug>/>` instead of a quoted `href`.

⚠️ **The Traditional guard needs its `ROOT` pointed at this repo.** Run it from
