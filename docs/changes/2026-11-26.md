## 2. ⚠️ AI crawler surface was stale by 11 posts per language

**Found while answering "how is the AI crawler working on traindecade".**

`static/llms.txt` claimed `## English posts (34)` and `## 中文文章 (34)`.
The repo held **45 + 45**. Eleven posts per language were missing.

The missing ones were the **newest** posts, and included the only page on the site
that converts in ZH (`pump-or-real-muscle`) plus `does-heavy-lifting-fry-your-cns`
(111 impressions, 0 clicks in 28d).

**Root cause is not the generator.** `scripts/gen_llms_txt.py` was correct and
already had a docstring explaining exactly this drift had happened before (it says
"silently drifted to 6 of 74 posts"). The file was hand-edited since, and **nothing
tested the generator output**. A generator with no test is a manual process with
extra steps.

**Fix:** new gate `tests/test_llms_txt_fresh.py` with 6 assertions — every EN post
listed, every ZH post listed, no ghost entries (404s handed to crawlers), heading
counts true, no duplicates, file exists. Written RED-first: it failed on the stale
file naming all 11 missing posts, then passed after regeneration.

Regenerated: 34+34 → **45+45**, 17,857 → 20,013 chars.

**Deliberate:** the test parses the shipped file; it does NOT shell out to the
generator. A test that regenerates to compare with itself passes forever.

## 3. ⚠️ Outbound-click tracker test had never worked in a production build

`scripts/test_outbound_tracking.js` failed for three stacked reasons. All three were
invisible because **the CI workflow never invoked this script** — only
`scripts/run_tests.sh` did, locally.

| # | defect | why it hid |
|---|---|---|
| 1 | hardcoded `/tmp/tdreview/public/...` | a scratch dir from one old review session; existed for the author only |
| 2 | regex required literal space `(function () {` | `hugo --minify` emits `(function(){` |
| 3 | regex required trailing `;` | minified output ends `})()` with no semicolon |
| 4 | after relaxing 2+3, lazy match grabbed the **email-capture** IIFE | page has 8 inline scripts; running the wrong one threw `getElementById is not a function` |
| 5 | stub anchor lacked `getAttribute` | the tracker now reads `data-ga`; stub modelled an older DOM |

**Fix:** resolve the path relative to the repo; anchor extraction on the
`outbound_click` marker and slice its enclosing `<script>` tag; add `getAttribute`
to the stub; assert the `data-ga` branch fires both `outbound_click` and the named
event. 7 cases now pass including a new `data-ga` case.

This matters because a broken outbound tracker is **silent** — no error, no data,
indistinguishable from "nobody clicked". That is the exact question GA4 exists to
answer for the GainCut CTA.
