First action layer added since the protein calculator (2026-09-19). Coverage now **2 of 90**

Routing table (first match wins, must stay consistent with the post's prose):

```
q1 redflag (night pain / fever / weight loss)    -> urgent   (clinician, promptly)
q3 neuro   (numbness / weakness / bladder-bowel) -> neuro    (clinician, then physio)
```

Five routes, all reachable and asserted. Output card gives **who to see / why / what to

### Harness pitfalls hit (recorded so the next widget does not re-pay them)

1. **The stub must set `el.value`** — the widget reads `el.value` off a checked radio.
   A shim that only stores `_value` makes every route fail while the widget is fine.
2. **Selector-slice off-by-one** — `"pr-q1"` is 5 chars; slicing 4 returned `pr-q` and
   every query missed.
3. **Language is captured at INIT, by design** — testing ZH by mutating `data-lang`
   after `eval` fails correctly. Re-`eval` with the new attribute for a ZH pass.
4. **Label matching must use the real rendered prefix** — the neuro route label starts
   "A clinician...", not with the words I assumed; matching on an invented substring
   reported 16 false failures.
